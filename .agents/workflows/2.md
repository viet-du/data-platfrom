description: Workflow steps
---

1. Read workspace documentation.
   Check relevant files such as README.md, working_rule.md, description.md, architecture.md, api.md, database.md, workflow.md, coding_convention.md, and related source files.

2. Identify the current project structure.
   Determine architecture, naming convention, coding style, existing modules, and stable files.

3. Restate the user requirement.
   Summarize what needs to be done, the target output, affected files, and constraints.

4. Stop if context is missing.
   Ask clarification questions if requirement, input/output, scope, logic, or expected behavior is unclear.

5. Propose a technical plan.
   Include:
   - Business requirement
   - Feature-level interpretation
   - Technical solution
   - Logic / AI solution
   - Implementation steps
   - Risks and limitations
   - Validation plan

6. Wait for user confirmation.
   Do not implement before approval.

7. Implement only the approved changes.
   Follow existing architecture, folder structure, naming convention, coding style, service/hook/helper/module boundaries, and security rules.

8. Do not touch unrelated stable code.
   Avoid broad refactoring, formatting, dependency changes, or structural changes unless explicitly approved.

9. Validate after implementation.
   Check:
   - Does it satisfy the requirement?
   - Are there breaking changes?
   - Are there side effects?
   - Are there security risks?
   - Does it follow naming and architecture?
   - Are tests or manual checks needed?

10. Final report.
   Return:
   - Files changed
   - What was wrong before
   - Why changes were made
   - Impact
   - Validation performed
   - Remaining risks / side effects
   - Completion estimate
